## Context

当前应用是 Flask + SQLite 单体服务，当前已采用 JWT Bearer 认证：验证签名、有效期及数据库撤销状态后，从数据库用户记录取得 `class_id`；材料表记录原文件位置和 `index_status`，上传仅保存原文件后即标记 indexed，并未抽取正文或建立可检索索引。材料列表、详情和下载已使用服务端班级范围过滤。现有依赖没有文本提取或向量检索组件，Compose 将 `/app/data` 保存在命名卷中。动机见 `proposal.md`，行为契约见 `specs/class-knowledge-retrieval/spec.md`。

## Goals / Non-Goals

**Goals:**

- 在现有 Flask/SQLite 单体和持久化卷中提供可运维的正文切分、向量嵌入、关键字/向量/混合检索与带引用问答，不要求单独部署向量服务。
- 让关系型材料记录成为权限和出处元数据的权威来源，并在检索前、检索后都验证班级范围。
- 兼容既有材料上传、列表和下载行为；为历史材料提供可重试的索引回填。
- 用可替换的提取、嵌入和向量存储边界，保持检索 API 与前端契约稳定。

**Non-Goals:**

- 问答限定为依据本班证据的单轮 RAG；不提供多轮历史、联网搜索、跨班问答或自动调用外部云端模型。
- 首期采用本地生成模型，模型路径与资源限制由部署配置提供；模型未就绪必须显式报错，不能将单纯检索结果冒充问答成功。
- 首期不做扫描件 OCR、图像/音视频识别、跨班共享、知识库管理后台或独立向量数据库集群。
- 不重做现有登录、角色授权、文件下载或班级数据模型。

## Decisions

### 本地双路索引，关系库保留权威元数据

- 首期采用嵌入式 Chroma 持久化向量库，存储目录放在 `/app/data/vector-index`，由现有 Compose 命名卷持久化；采用本地 `sentence-transformers` 嵌入模型（默认轻量多语言模型 `paraphrase-multilingual-MiniLM-L12-v2`），模型名称/路径可通过服务端配置替换，不向第三方发送课堂内容。
- SQLite 新增片段元数据表，保存 `material_id`、`class_id`、稳定片段 ID、片段原文、定位信息和内容版本/哈希。Chroma 只保存向量及可反查的片段 ID/班级元数据；最终来源标题和材料授权仍从 SQLite 联查，避免向量元数据成为独立权限事实来源。
- 同时新增 SQLite FTS5 关键字索引。中文用固定版本的 jieba 搜索分词，英文按统一大小写和词边界处理；入库和查询使用相同规则及版本，原文另存不被分词文本覆盖。将词项逐个转义并构造参数化 MATCH 查询，首期多词按 OR 召回，不将用户输入直接作为 FTS 运算表达式。仅有标点、无法产生词项的 keyword 查询返回空结果。
- FTS 按班级建立逻辑独立的索引表，表名只由服务端数据库中的整数班级 ID 构造；统计、BM25 排名和候选 limit 均局限本班，避免全局词频影响跨班可观测结果。查询同时联查当前材料状态及版本。
- 使用 FTS5 与 Chroma 两路互补，而非仅保留全文匹配或仅依赖向量。沿用嵌入式部署避免新增必需的向量数据库服务；启动时检查 FTS5 能力，缺失时明确提示部署错误。

### 将材料可下载状态与搜索索引状态分离

- 现有 `materials.index_status` 继续表示原文件入库状态，以免索引失败导致已上传文件无法下载或破坏当前列表契约。新增 `search_index_status`（pending/indexed/failed）及可向授权用户展示的简短失败原因；检索只选择 `search_index_status = 'indexed'` 的材料。
- SQLite 迁移为已有材料添加 `search_index_status = 'pending'`，不改动其原文件状态。新增幂等 `reindex-materials` CLI 命令按材料逐条回填；回填完成前旧材料仍可列出和下载，但不进入检索结果。
- 新上传流程在原文件存储成功后将搜索索引状态设为 pending，随后同步执行文本提取、切块、关键字索引、嵌入和向量写入；全部成功后才标记 indexed。提取/嵌入/向量写入失败时保留原文件和材料记录，搜索状态设为 failed，并向上传者返回不含内部路径或堆栈的可理解状态。同步处理首期避免增加任务队列；大文件大小和请求时限配置化。
- 重新索引按材料 ID、正文哈希、处理配置版本和片段序号生成稳定 ID，先使材料不可检索，再替换该材料的旧片段、FTS 记录及向量，全部写入成功后原子更新 SQL 状态；失败时删除本轮残留向量并保持 failed，避免重复命中或旧内容继续被检索。CLI 可重试 pending/failed 项并清理无主向量。记录嵌入模型标识、维度、分词与切分配置版本；模型/维度变化时使用新集合并回填，不混查不同向量空间。同一材料索引通过数据库租约与处理代次串行化，发布时比较代次，过期作业不得覆盖新结果。崩溃遗留 pending 可由 CLI 恢复。

### 结构化文本提取和可复现的来源定位

- 首期支持 UTF-8 `.txt`、Markdown `.md`、文本型 PDF 和 DOCX。TXT/Markdown 以标题层级和段落保留定位信息；PDF 保存页码；DOCX 保存标题路径和段落序号。扫描型 PDF、空文本和不支持格式明确标记为搜索索引失败，不伪造空索引；OCR 留待后续变更。
- 使用按嵌入模型 tokenizer 计数的重叠分块，最大长度不超过所配置模型的有效输入上限并预留特殊 token 空间；重叠约为有效块长的 10%，优先按段落/标题边界切分。不得固定 500 token 后让模型静默截断。每个片段保存原文和定位信息；API 返回受限长度的原文片段，不调用生成模型改写。
- 对同一材料的重新上传/重建，以材料 ID + 正文哈希 + 处理配置版本 + 片段序号稳定识别版本，并清除旧片段，确保引用指向当前文件内容。

### 三种检索共享班级边界与来源协议

- 新增 `POST /api/search`，JSON 请求为 `query`、`mode`（keyword/vector/hybrid，默认 hybrid）、`limit`（默认 5，范围 1–20，拒绝布尔值和非整数）。query 须为去除首尾空白后非空字符串，最长 2000 字符；无效 JSON/字段类型/模式返回 400。兼容忽略客户端 class_id，其他未知字段返回 400。
- 复用 JWT `login_required()`。范围仅来自 `g.user['class_id']`，FTS 在本班分区内取候选，Chroma 查询必须携带班级过滤。每路最多召回 50 个候选，在融合前以 SQLite 联查当前材料状态、版本及班级，最后再取 limit，绝不全库召回后仅在前端过滤。
- keyword 使用本班 BM25 排序；vector 使用归一化嵌入的余弦相似度，应用服务端可配置的最小相似度阈值（初始 0.35，真实模型验收时校准并记录）。hybrid 对两路有效候选采用等权 RRF：每路贡献 `1/(60+rank)`，按片段 ID 去重，同分以片段 ID 稳定排序。向量低相关候选在融合前剔除，避免 top-k 总返回无关内容。
- 任一当前模式所需依赖失败返回 503，不把错误当空结果，也不静默降级。向量库故障时，显式 keyword 请求可继续查已经完整发布的索引；新索引仍须两路齐备才发布。
- 响应包含 mode 和 results；每项含 chunk_id、content_version、material_id、title、filename、原文 excerpt、rank、location（PDF 页码或页码范围、标题路径、段落范围、兜底片段序号）、source_url 和 download_url。不向用户暴露全局统计、内部路径或距离分数。
- 新增 `GET /api/knowledge/chunks/<chunk_id>` 返回完整原文与来源。必须认证、联查本班当前版本和可检索状态；不存在、跨班、过期片段统一返回 404，不泄露存在性。索引重建时内容/配置不变可保留稳定 ID，版本改变后旧引用失效，不改指新片段。
- 来源的原文件入口复用 `/api/materials/<id>/download`。前端用现有带 Bearer 的 fetch 下载流程，Token 不放在 URL 中；原文同样通过认证 API 查看，不能依赖普通链接自动附带 Authorization。

### 单轮问答复用检索，生成与证据校验分离

- 新增 `POST /api/knowledge/ask`，请求为 question 与 mode（默认 hybrid）；问题长度与检索 query 相同，忽略 class_id，不接受客户端提供的证据片段。返回 `status`（answered/insufficient_evidence）、answer 和 citations；每条 citation 包含编号及完整的来源协议字段。无足够证据返回 HTTP 200、固定提示“本班知识库暂无足够依据”和空 citations；依赖不可用或超时返回 503，结构化生成输出无效返回 502。
- 调用同一检索服务，默认最多选 5 个已核验片段。按生成模型 tokenizer 限制上下文，预留指令、问题及输出预算；保留完整证据单元及其位置，超预算优先舍弃低排名单元。没有有效证据时不调用生成器。回答只基于本次证据，不使用对话历史、联网信息或全库兜底。
- 沿用原方案的本地数据处理原则，首期通过 Transformers 本地加载 Qwen2.5-1.5B-Instruct（验收修订 `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`），由 `QA_MODEL_PATH` 指向预先准备的模型文件，禁用运行时自动联网下载及远程模型代码。模型名称、修订、上下文窗口、内存需求和实测延迟在部署验收时记录。嵌入器、生成器均通过适配层注入，常规测试用确定性替身。未配置模型时仅问答返回明确 503，不能阻止登录、材料下载或检索。
- 生成适配器产出结构化结果：answerable、逐项陈述及各自的 evidence_ids 和 supporting_quote。为避免小模型把 JSON 占位文字当成答案，先让本地模型生成完整草稿，再独立选择支持草稿的原文引文；草稿与引用均不可信，随后按陈述执行下述校验。模型上下文使用服务端分配的短引用别名，返回时映射为真实片段 ID。服务端校验引用只来自本次已授权证据，支持引文必须为原文子串；每项知识性陈述均须引用。用独立的本地证据支持检查步骤逐项判断陈述能否由引文推出；无法判断或不支持的回答按依据不足处理，不能仅凭引用 ID 合法就认为事实得到支持。该检查仍有模型误判风险，真实模型验收须包含不支持的陈述与诱导用例。
- 将材料明确标记为不可信证据，指令与证据分区传入；不提供工具执行能力。生成器不得扩展班级范围或构造下载地址；引用对象与 URL 均由服务端构建。返回前再次验证所引用材料的当前版本和授权，变化时丢弃答案，返回可重试的 409（证据已更新）。
- 默认非流式响应，校验完成才展示回答。限制并发生成数、最大输入/输出 token 和总超时；隔离到可终止的本地推理工作进程，超时终止作业释放资源，忙时返回 503。代理与应用超时应大于内部处理超时。首期不持久化问题、回答或跨用户共享缓存。

### 前端和验证策略

- 在现有课堂工作台增加教师、学生共用的三种检索模式选择、检索框、问答操作和结果区域；通过 `/api/search` 请求，只渲染文本节点/转义内容，并显示片段、材料标题、页码/章节/片段序号及受保护的下载操作。问答独立展示回答和编号引用，点击引用加载完整原文；明确区分加载、无结果、依据不足、证据已更新、索引/模型不可用和请求失败。旧请求晚到时不得覆盖新结果，登出清空问答内容。
- 扩展现有材料 API 的状态字段以显示搜索索引状态（不改变原始文件的下载资格）；索引失败原因只向同班已认证用户显示，且需限制和净化错误内容。
- 测试以临时 SQLite、临时向量目录和可注入的确定性嵌入/检索适配器隔离，不在常规测试中下载模型或访问网络。覆盖教师/学生检索、无认证、跨班同词命中、伪造 `class_id`、无结果、定位回传、索引失败/重试/替换、存量回填及向量库故障关闭；另验证 Compose 数据卷中的双路索引持久化。增加中文词项、同义改写、RRF 去重排序、全部模式隔离、引用越权/过期、无依据拒答、材料指令注入、模型超时和无效引用用例。真实嵌入和生成模型需另做显式离线验收，不能以替身测试代替语义质量验收。

## Risks / Trade-offs

- [Risk] 本地嵌入模型和向量库增加镜像体积、首次启动耗时及 CPU 使用 → 固定轻量默认模型并允许预缓存/配置替换；检索和索引边界可替换，测试注入确定性模型。
- [Risk] SQLite 与 Chroma 无法共用事务，失败可能留下孤儿或半成品向量 → 仅在 SQL `search_index_status` 为 indexed 时接受结果，采用稳定 ID、版本发布、串行索引、补偿删除和可重复回填命令；向量查询/校验异常一律失败关闭。
- [Risk] 某一检索路径漏传班级过滤可能泄露其他课堂内容 → 先对向量查询应用认证班级过滤，再以 SQLite 再验证；跨班同词和伪造班级测试作为发布门槛。
- [Risk] 不支持格式或扫描 PDF 会有材料不能搜索 → 保留原文件正常下载，明确暴露索引失败状态与原因，并在规格外避免暗示已支持 OCR。
- [Risk] 历史材料迁移后不会立即可搜索 → 将它们标记为搜索 pending，提供显式批量回填和进度/失败状态，不影响历史文件列表与下载。

- [Risk] 本地生成模型资源需求与质量取决于部署模型 → 配置模型路径、限制推理并发/预算/超时，显式准备模型并执行中文检索和引用问答验收；模型故障不拖垮材料功能。
- [Risk] 引用形式正确但陈述无证据支持 → 校验原文引文、逐项执行证据支持检查，遇到不确定拒答；保留原文供用户核验，不声称能自动消除所有幻觉。
- [Risk] 中文分词或阈值导致漏检 → 固定分词版本，建立中文关键字、同义问题和不相关问题样例，校准阈值；配置变化记录版本并重建索引。

## Migration Plan

1. 以向后兼容方式增加搜索状态、片段元数据表、班级 FTS 表和向量库目录配置；已有 `index_status` 和文件路径语义保持不变。
2. 部署提取器/嵌入/向量适配器及幂等回填命令，在持久卷上创建 Chroma 索引；先用小批量历史材料验证容量、语言检索和来源定位。
3. 接入新上传同步索引与受班级过滤的检索 API，增加前端三模式检索交互；运行隔离、索引失败/重试和来源测试后开放检索。准备本地生成模型及资源配置，验收问答和引用后开放问答入口。
4. 部署后继续回填历史材料并监控 pending/failed；回滚时隐藏检索及问答 UI/禁用新增 API，保留原文件和 SQLite 材料记录。若移除向量目录，历史材料可通过回填命令重建索引。

## Validation Notes

- 本地生成模型与嵌入模型已选定并完成样例验收；模型修订、资源消耗和延迟记录在 `docs/knowledge-acceptance.md`。替换权重或部署环境后须重新执行真实模型验收，固定接口与 QA_MODEL_PATH 配置保持不变。
