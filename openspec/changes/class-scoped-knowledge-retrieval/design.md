## Context

当前应用是 Flask + SQLite 单体服务，session 中的用户关联一个 `class_id`；材料表记录原文件位置和 `index_status`，上传仅保存原文件后即标记 indexed，并未抽取正文或建立可检索索引。材料列表、详情和下载已使用服务端班级范围过滤。现有依赖没有文本提取或向量检索组件，Compose 将 `/app/data` 保存在命名卷中。动机见 `proposal.md`，行为契约见 `specs/class-knowledge-retrieval/spec.md`。

## Goals / Non-Goals

**Goals:**

- 在现有 Flask/SQLite 单体和持久化卷中提供可运维的内容索引与语义检索，不要求单独部署向量服务。
- 让关系型材料记录成为权限和出处元数据的权威来源，并在检索前、检索后都验证班级范围。
- 兼容既有材料上传、列表和下载行为；为历史材料提供可重试的索引回填。
- 用可替换的提取、嵌入和向量存储边界，保持检索 API 与前端契约稳定。

**Non-Goals:**

- 不生成综合答案或摘要，不引入 RAG 对话、外部大模型调用或回答事实性判断。
- 首期不做扫描件 OCR、图像/音视频识别、跨班共享、知识库管理后台或独立向量数据库集群。
- 不重做现有登录、角色授权、文件下载或班级数据模型。

## Decisions

### 采用本地持久化向量索引，关系库保留权威元数据

- 首期采用嵌入式 Chroma 持久化向量库，存储目录放在 `/app/data/vector-index`，由现有 Compose 命名卷持久化；采用本地 `sentence-transformers` 嵌入模型（默认轻量多语言模型 `paraphrase-multilingual-MiniLM-L12-v2`），模型名称/路径可通过服务端配置替换，不向第三方发送课堂内容。
- SQLite 新增片段元数据表，保存 `material_id`、`class_id`、稳定片段 ID、片段原文、定位信息和内容版本/哈希。Chroma 只保存向量及可反查的片段 ID/班级元数据；最终来源标题和材料授权仍从 SQLite 联查，避免向量元数据成为独立权限事实来源。
- 选择 Chroma 而不是只用 SQLite FTS5，是因为规格要求自然语言语义相关性；FTS5 可作为将来的混合检索优化，但不能替代语义检索。选择嵌入式 Chroma 而非独立 Qdrant/托管服务，是为了保留当前 Compose 的单体部署和课堂数据本地化。

### 将材料可下载状态与搜索索引状态分离

- 现有 `materials.index_status` 继续表示原文件入库状态，以免索引失败导致已上传文件无法下载或破坏当前列表契约。新增 `search_index_status`（pending/indexed/failed）及可向授权用户展示的简短失败原因；检索只选择 `search_index_status = 'indexed'` 的材料。
- SQLite 迁移为已有材料添加 `search_index_status = 'pending'`，不改动其原文件状态。新增幂等 `reindex-materials` CLI 命令按材料逐条回填；回填完成前旧材料仍可列出和下载，但不进入检索结果。
- 新上传流程在原文件存储成功后将搜索索引状态设为 pending，随后同步执行文本提取、切块、嵌入和向量写入；全部成功后才标记 indexed。提取/嵌入/向量写入失败时保留原文件和材料记录，搜索状态设为 failed，并向上传者返回不含内部路径或堆栈的可理解状态。同步处理首期避免增加任务队列；大文件大小和请求时限配置化。
- 重新索引按材料内容哈希和片段序号生成稳定 ID，先使材料不可检索，再替换该材料的旧片段/向量，全部写入成功后原子更新 SQL 状态；失败时删除本轮残留向量并保持 failed，避免重复命中或旧内容继续被检索。CLI 可重试 pending/failed 项并清理无主向量。

### 结构化文本提取和可复现的来源定位

- 首期支持 UTF-8 `.txt`、Markdown `.md`、文本型 PDF 和 DOCX。TXT/Markdown 以标题层级和段落保留定位信息；PDF 保存页码；DOCX 保存标题路径和段落序号。扫描型 PDF、空文本和不支持格式明确标记为搜索索引失败，不伪造空索引；OCR 留待后续变更。
- 使用重叠分块（默认约 500 个模型 token、重叠约 60 token），尽可能在段落/标题边界切分。每个片段保存原文和定位信息；API 返回受限长度的原文片段，不调用生成模型改写。
- 对同一材料的重新上传/重建，以材料 ID + 正文哈希 + 片段序号稳定识别版本，并清除旧片段，确保引用指向当前文件内容。

### 检索接口在向量查询前强制服务端范围

- 新增 `POST /api/search`，请求只接受 `query` 与可选的 `limit`（默认 5，服务端限制最大 20）；空白、缺失、类型错误或超限查询返回 400。复用现有认证装饰器，教师和学生均可检索，不增加角色例外。
- 每次请求从 `g.user['class_id']` 取得范围，在 Chroma 查询中传入该班级过滤条件，绝不使用请求中的 `class_id`。随后对候选片段以 SQLite 联查 `materials.id`、班级和 `search_index_status` 再做授权验证；向量库不可用或查询异常时失败关闭，不回退为全库查询。
- 响应包含原文片段、材料 ID/标题/文件名、相关性顺序和定位（页码、标题路径或稳定片段序号）；不返回绝对存储路径、全局命中数或其他班级的距离/排名信息。来源链接只使用已存在的受保护材料下载入口。

### 前端和验证策略

- 在现有课堂工作台增加教师、学生共用的检索框和结果区域；通过 `/api/search` 请求，只渲染文本节点/转义内容，并显示片段、材料标题、页码/章节/片段序号及受保护的下载链接。明确提供加载、无结果、索引不可用和请求失败状态，不生成回答。
- 扩展现有材料 API 的状态字段以显示搜索索引状态（不改变原始文件的下载资格）；索引失败原因只向同班已认证用户显示，且需限制和净化错误内容。
- 测试以临时 SQLite、临时向量目录和可注入的确定性嵌入/检索适配器隔离，不在常规测试中下载模型或访问网络。覆盖教师/学生检索、无认证、跨班同词命中、伪造 `class_id`、无结果、定位回传、索引失败/重试/替换、存量回填及向量库故障关闭；另验证 Compose 数据卷中的索引持久化。

## Risks / Trade-offs

- [Risk] 本地嵌入模型和向量库增加镜像体积、首次启动耗时及 CPU 使用 → 固定轻量默认模型并允许预缓存/配置替换；检索和索引边界可替换，测试注入确定性模型。
- [Risk] SQLite 与 Chroma 无法共用事务，失败可能留下孤儿或半成品向量 → 仅在 SQL `search_index_status` 为 indexed 时接受结果，采用稳定 ID、补偿删除和可重复回填命令；向量查询/校验异常一律失败关闭。
- [Risk] 某一检索路径漏传班级过滤可能泄露其他课堂内容 → 先对向量查询应用认证班级过滤，再以 SQLite 再验证；跨班同词和伪造班级测试作为发布门槛。
- [Risk] 不支持格式或扫描 PDF 会有材料不能搜索 → 保留原文件正常下载，明确暴露索引失败状态与原因，并在规格外避免暗示已支持 OCR。
- [Risk] 历史材料迁移后不会立即可搜索 → 将它们标记为搜索 pending，提供显式批量回填和进度/失败状态，不影响历史文件列表与下载。

## Migration Plan

1. 以向后兼容方式增加搜索状态、片段元数据表和向量库目录配置；已有 `index_status` 和文件路径语义保持不变。
2. 部署提取器/嵌入/向量适配器及幂等回填命令，在持久卷上创建 Chroma 索引；先用小批量历史材料验证容量、语言检索和来源定位。
3. 接入新上传同步索引与受班级过滤的检索 API，增加前端检索交互；运行隔离、索引失败/重试和来源测试后开放检索。
4. 部署后继续回填历史材料并监控 pending/failed；回滚时隐藏检索 UI/禁用搜索 API，保留原文件和 SQLite 材料记录。若移除向量目录，历史材料可通过回填命令重建索引。

## Open Questions

无。首期格式、同步索引方式、向量后端和嵌入模型均在本设计中明确；后续替换模型或增加格式不改变已定义的检索与来源行为。
