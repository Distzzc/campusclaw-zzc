## Context

现有项目是单体 Flask + SQLite 应用，页面通过 `render_template_string` 返回两段极简 HTML；认证和材料能力已经由服务端提供 `/login`、`/logout`、`/api/me`、`/api/materials` 及上传接口。前端必须在同一 Flask 服务中交付，复用现有 session 和服务端班级过滤，不把 UI 隐藏当成授权。行为契约见 `specs/web-classroom-frontend/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用正式模板、静态 CSS 和渐进增强 JavaScript 替换内联 HTML 页面。
- 建立登录、认证恢复、角色仪表盘、材料列表和教师上传的完整用户流程。
- 为加载、空数据、网络失败、401 和 403 提供一致且可理解的状态反馈。
- 保持 Flask 单服务部署和现有 API/安全边界，支持桌面与移动视口。

**Non-Goals:**

- 不重新实现密码认证、session 签发、角色授权或班级数据过滤。
- 不增加检索问答、对话助手、作业提交与批改、SSO 或独立前端部署服务。
- 不在本变更中引入复杂状态管理、离线缓存或服务端渲染之外的全量 SPA 架构。

## Decisions

### Flask 模板与静态资源

- 将页面拆分为 `templates/base.html`、`templates/login.html`、`templates/dashboard.html` 等模板，并将样式和交互脚本放在 `static/`。相较继续使用 `render_template_string`，模板文件可以复用布局、获得清晰的资源缓存边界并支持渐进增强。
- 采用 Flask 服务端渲染作为首屏和无 JavaScript 的基础路径，使用原生 JavaScript `fetch` 增强列表刷新、上传进度和错误反馈；不引入 React/Vite 依赖，避免为当前单体服务增加独立构建和部署链路。
- 视觉层采用明确的课堂工作台结构：窄侧栏/顶部身份区、主内容区、材料列表和教师上传面板；CSS 使用变量、响应式网格和可见焦点样式，不依赖默认浏览器表单外观。

### 认证与前端状态

- 页面首屏由 Flask 根据 session 进入登录或仪表盘；前端加载时调用 `/api/me` 获取角色和班级，用户信息只保存在内存状态，不存储密码或自行复制 session 内容。
- API 客户端集中处理 401、403、网络错误和 JSON 错误格式：401 清理状态并跳转登录，403 保留页面并显示无权限提示，其他错误显示可重试反馈。
- 登出继续调用现有 `/logout`，成功后清理视图状态并回到登录页。前端角色判断只用于呈现体验，服务端授权仍是最终控制。

### 材料工作流

- 仪表盘首次加载调用 `/api/materials`，列表组件只渲染服务端返回的数据；不接受或发送用于越权的班级参数。
- 教师上传使用 `FormData` 将标题和文件提交到 `/api/materials`，提交按钮在请求期间禁用，成功响应后重新加载列表；学生没有上传表单，即使直接调用接口也由服务端返回 403。
- 使用明确的状态模型：`loading`、`ready`、`empty`、`error`、`uploading`、`success` 和 `forbidden`。这样可以避免网络请求时空白页面和错误状态覆盖成功数据。

### 响应式与可访问性

- 桌面布局使用受限内容宽度和材料表格/列表，移动端切换为单列材料卡片；上传控件在窄屏全宽排列。使用真实 `label`、按钮文本、键盘焦点和 `aria-live` 错误/成功提示。
- 不用颜色作为唯一状态信号，错误、成功和禁用状态同时提供文字和图标/边框差异；长文件名使用可换行或截断策略，防止溢出。

### 验证

- 使用 Flask 测试客户端验证页面路由、401/403 行为和服务端模板输出；使用浏览器端到端测试验证登录跳转、教师/学生视图、上传刷新和错误反馈。
- 在桌面和移动视口执行截图/布局检查，确认无横向滚动、控件重叠和不可见文本；使用 Compose 启动后从 `http://localhost:<APP_PORT>` 验证同一服务提供页面和 API。

## Risks / Trade-offs

- [Risk] 服务端渲染与 JavaScript 状态可能出现重复逻辑 → 保留服务端页面作为权威初始状态，将 JavaScript 限定为请求、状态反馈和局部刷新。
- [Risk] UI 隐藏上传按钮被误认为权限控制 → 在所有上传请求中继续依赖服务端 403，并把学生直接调用作为端到端测试场景。
- [Risk] 移动端材料标题或文件名过长导致布局溢出 → 使用 CSS 换行、最小列宽和长文本断行测试覆盖。
- [Risk] 当前 API 错误格式不完全统一 → 前端提供通用错误解析，并在不改变权限语义的前提下统一必要的页面错误响应。

## Migration Plan

1. 新增模板与静态资源，并让 `/`、`/login` 和 `/materials` 使用新页面；保留现有 API 路径和 session 行为。
2. 接入认证状态、材料列表和上传交互，先验证教师/学生角色差异与 401/403 处理，再移除旧的内联 HTML 常量。
3. 在测试和 Compose 环境执行桌面/移动端验收；若前端出现问题，可回滚模板和静态资源，服务端 API 与数据保持不变。
