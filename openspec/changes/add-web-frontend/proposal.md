## Why

现有系统已经具备登录、角色授权、班级隔离和材料接口，但用户只能看到内联的原生 HTML 表单，无法形成可用的课堂工作界面。需要增加正式 Web 前端，让教师和学生能够清晰完成登录、查看本班材料和上传材料，同时继续把权限判断交给现有服务端。

## What Changes

- 将极简内联页面替换为正式的响应式 Web 界面，包含登录页、教师/学生仪表盘和本班材料列表。
- 增加基于现有认证会话的前端登录态恢复；未登录访问受保护页面时跳转登录页。
- 教师界面提供材料上传、上传中、成功和失败反馈；学生界面提供本班材料只读查看，不显示上传操作。
- 前端通过现有 `/api/me`、`/api/materials` 和登录/登出接口交互，不在客户端实现或替代角色权限、密码校验和班级隔离。
- 增加统一的加载、空状态、错误状态和 401/403 处理，保证桌面和移动视口可用。

## Capabilities

### New Capabilities

- `web-classroom-frontend`: 定义课堂系统登录、角色仪表盘、材料列表、教师上传、学生只读访问和响应式错误反馈的前端行为。

### Modified Capabilities

无。现有认证与知识库 capability 的服务端要求不变，前端仅消费其已存在的接口和安全边界。

## Impact

- 新增或重构 Flask 模板、静态 CSS/JavaScript 以及可能的前端构建依赖；移除当前内联 HTML 页面实现。
- 复用现有登录会话和 `/api/me`、`/api/materials` 接口，必要时只补充页面所需的非安全性响应字段，不改变授权语义。
- 需要增加前端单元/端到端验证，覆盖未登录跳转、教师/学生视图差异、上传反馈、错误处理和移动视口布局。
- Docker Compose 继续通过同一个 Flask 服务提供前端和 API，不引入独立前端部署服务作为本变更的必需条件。
