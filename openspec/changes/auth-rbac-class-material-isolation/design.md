## Context

本仓库目前只有 OpenSpec 规划目录，没有可依赖的应用代码、技术栈、数据库或部署配置。本设计采用 Flask + SQLite 作为最小可运行栈；如果实现阶段改用等价栈，仍必须保留相同的 HTTP 行为、服务端授权和数据边界。动机与范围见 `proposal.md`，行为契约见 `specs/secure-class-knowledge-base/spec.md`。

## Goals / Non-Goals

**Goals:**

- 建立统一的认证上下文，使每个受保护请求都能得到可信的用户、角色和班级身份。
- 将角色授权和班级过滤放在服务端请求链路中，覆盖上传、列表、读取和其他知识库操作。
- 让材料元数据、原始文件和知识库索引保持可追踪的一致关系。
- 提供可重复的 Docker Compose 启动、环境变量配置和健康检查验证路径。

**Non-Goals:**

- 不在本变更中定义注册、密码找回、多因素认证或管理员后台。
- 不实现检索问答、对话助手、作业提交与批改、SSO 或生产级高可用。
- 不规定具体前端视觉设计、知识库检索排序或跨班级共享流程。
- 不把客户端隐藏按钮视为权限控制，也不允许前端负责班级隔离。

## Decisions

### Flask 应用、会话与密码

- 使用 Flask 提供页面路由和 JSON API；登录成功后建立服务端可验证的认证上下文，至少包含用户 ID、角色和班级 ID。优先使用 Flask 的服务端 session 配合 HttpOnly、Secure、SameSite cookie；若采用令牌，令牌也必须由服务端密钥签发并设置过期时间。
- 使用 Flask 的请求前处理钩子或等价中间件解析认证上下文；无身份的页面请求重定向到登录页，无身份的 API 请求返回 401。授权失败统一返回 403，并避免在错误消息中泄露跨班级资源是否存在。
- 使用 Argon2id；运行时不支持时才使用经审查的等价自适应密码哈希方案。登录比较使用库提供的安全校验接口，明文密码只存在于请求处理瞬间，不进入日志、响应或 SQLite。

### SQLite 数据模型与预置数据

- 使用 SQLite 保存用户、班级、材料和索引状态；至少包括 `users`、`classes`、`materials` 以及用户角色和班级归属字段。材料记录保存 `class_id`、创建者、原始文件引用、索引状态和时间信息。
- 通过数据库迁移或幂等初始化脚本创建表，并提供仅在开发/测试配置启用的预置数据命令：A/B 两个班级、每班教师和学生账号，以及可验证的哈希密码。生产启动不得自动加载预置账号或测试材料。
- SQLite 文件放入 Compose 命名卷或绑定卷，确保容器重启后用户和材料记录保留；测试使用独立数据库文件，避免污染开发数据。

### 服务端授权与班级过滤

- 在 Flask 路由层统一执行认证，在业务服务层执行角色与班级授权；SQLite 查询也必须带服务端解析出的 `class_id`，形成纵深防御。
- 上传接口只接受材料内容和必要的材料元数据，不把请求中的 `class_id` 当作权限依据；归属班级从认证身份取得。读取、列表和写操作同样使用该范围。
- 材料详情和修改操作优先使用“资源 ID + 当前用户 class_id”的联合查询；找不到授权范围内资源时返回一致的 403/不可访问结果，避免通过 404 差异泄露其他班级资源。
- 对已认证但不具备权限的请求使用一致的未授权语义；跨班级请求不得通过错误消息、列表计数或资源元数据泄露目标材料是否存在。相比只在 UI 过滤，这能保护 API 和直接调用者。

### 上传数据流与知识库写入

- 上传数据流为：认证并确认角色为教师 → 从认证上下文取得 `class_id` → 校验文件和元数据 → 在 SQLite 创建待处理材料记录 → 将原始文件写入持久化目录 → 写入知识库适配器并记录索引状态 → 事务性更新为成功 → 返回材料记录。
- 学生或其他无上传权限的角色在 Flask 路由/服务层直接返回 403，数据流不得进入文件存储或知识库索引。
- 采用“先登记待处理状态，再完成存储与索引，最后标记成功”的可恢复流程；任何存储或索引失败都必须将记录标记为失败或清理它，使默认列表只返回成功可用的记录。
- 原始材料存储与知识库索引通过内部适配边界隔离。当前最小实现可以使用 Compose 持久化卷和本地索引适配器；后续替换对象存储或向量/全文索引不改变上传和列表契约。

### Docker Compose 与 `GET /health`

- Docker Compose 编排 Flask 应用，并挂载 SQLite 数据库文件和材料存储目录的持久化卷；通过环境变量注入 `FLASK_ENV`、session/签名密钥、数据库路径和存储路径，提交 `.env.example` 而不提交真实值。
- `GET /health` 是 Flask 提供的公开轻量 liveness 端点，不需要登录，应用进程正常时返回成功 JSON；Compose healthcheck 使用该端点，不把客户端提供的密钥或认证信息传给健康检查。
- Compose 启动流程执行幂等数据库初始化，开发/测试环境可显式执行预置数据加载；生产配置关闭预置数据。

### 验证策略

- 用接口级测试覆盖教师和学生登录、错误凭据、未登录页面/API、学生直接上传、教师上传、同班列表、跨班级读取/列表/上传以及密钥不从请求读取。
- 用持久化集成测试确认密码字段不是明文、预置数据可重复加载、上传成功后材料记录和知识库索引可见、失败不会出现在默认列表；用 Compose smoke test 验证启动和 `/health`。

## Risks / Trade-offs

- [Risk] cookie 会话可能遭遇 CSRF 或配置错误 → 使用 SameSite 和 CSRF 防护策略，生产环境强制 Secure，并在集成测试中验证会话属性。
- [Risk] 原始材料已写入但知识库索引失败会产生孤儿数据 → 使用显式索引状态、重试/补偿任务和默认过滤，禁止把未完成记录当成成功材料返回。
- [Risk] 多租户查询遗漏 class ID 造成数据泄露 → 在领域服务和数据访问层都要求范围参数，并加入跨班级否定测试作为发布门槛。
- [Risk] 绿色项目缺少既有技术栈约束，初始选型可能需要调整 → 把数据库、存储和索引封装在适配器后，先锁定接口契约和安全测试，再根据实现仓库选择具体库。

## Migration Plan

1. 初始化应用、持久化依赖和 Compose 配置，注入开发/测试环境所需的非生产密钥。
2. 建立用户、班级、材料和索引状态模型，创建测试教师、学生和至少两个班级的数据。
3. 先上线认证与服务端授权，再接入材料存储和知识库写入；用接口测试验证拒绝路径后开放前端上传入口。
4. 在部署前执行迁移、认证/隔离测试和 Compose smoke test；回滚时停止新接口并恢复应用镜像，保留数据迁移的向后兼容字段。
