## Why

项目需要一个可用于课堂场景的基础访问控制能力：教师和学生必须能够安全登录，学生不能获得教师上传权限，且材料不能跨班级泄露。当前没有既有 capability 规格或应用实现可供复用，本变更建立这套服务端强制执行的安全边界，并让教师上传的材料真正进入本班知识库。

## What Changes

- 增加教师和学生的账号密码登录、会话/令牌认证，以及受保护页面未登录时跳转登录页的行为。
- 增加教师、学生角色授权；上传材料接口只允许教师调用，学生直接调用接口必须被拒绝。
- 增加班级归属与服务端班级隔离：材料查询、读取和上传均按用户所属班级校验，跨班级访问被拒绝。
- 增加材料上传到知识库的持久化记录，并支持本班材料列表查询，查询结果包含刚上传的材料记录。
- 密码只以强哈希形式存储，禁止明文密码；密钥和其他敏感配置仅从服务端环境变量读取。
- 提供 Docker Compose 启动方式和 `GET /health` 健康检查端点。

## Capabilities

### New Capabilities

- `secure-class-knowledge-base`: 定义账号认证、角色权限、班级边界、材料上传与知识库列表查询的可观察行为。

### Modified Capabilities

无。项目当前没有既有 capability 规格。

## Impact

- 新增认证、授权、用户/角色/班级、材料和知识库相关的数据模型、服务端接口与访问控制中间件。
- 影响受保护页面的前端路由守卫和登录流程，但所有权限与班级过滤必须在服务端再次执行。
- 需要安全密码哈希、服务端密钥配置、持久化存储以及材料存储/知识库写入依赖。
- 增加 Docker Compose 编排、环境变量配置、健康检查和认证/越权/跨班级隔离测试。

## Non-goals

- 本课不实现知识库检索问答。
- 本课不实现对话助手。
- 本课不实现作业提交与批改。
- 本课不实现 SSO（单点登录）。
- 本课不承诺生产级高可用（HA）、多地域部署、自动故障转移或完整灾备体系。
