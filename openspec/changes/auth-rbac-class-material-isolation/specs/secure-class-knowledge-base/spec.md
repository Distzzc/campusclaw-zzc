## Purpose

为课堂材料提供可验证的身份认证、角色授权和班级数据边界，使教师能够将材料写入本班知识库，同时阻止未登录、学生或其他班级用户越权访问。

## ADDED Requirements

### Requirement: 用户可以使用绑定角色的账号进行认证

系统 SHALL 允许教师账号和学生账号使用账号标识与密码进行认证，并 SHALL 为每个已认证用户关联且仅关联一个受支持的角色和班级归属。系统 MUST 仅存储单向密码哈希，且 MUST 永不持久化或返回明文密码。

#### Scenario: 教师登录成功
- **WHEN** 教师提交有效的账号凭据
- **THEN** 系统建立包含教师身份和角色的已认证会话或令牌，且不返回密码

#### Scenario: 学生登录成功
- **WHEN** 学生提交有效的账号凭据
- **THEN** 系统建立包含学生身份和角色的已认证会话或令牌，且不返回密码

#### Scenario: 无效凭据被拒绝
- **WHEN** 用户提交不存在的账号或错误的密码
- **THEN** 系统拒绝认证，且不建立已认证会话或令牌

### Requirement: 系统提供可重复的预置账号和班级数据

系统 SHALL 在开发和测试环境提供可重复加载的预置数据，至少包含两个班级、每个班级至少一名学生和一名教师，并 SHALL 为预置账号设置非明文密码哈希。预置数据 MUST 仅用于非生产环境，不能覆盖或泄露生产环境的真实账号和密钥。

#### Scenario: 预置数据包含两个隔离班级
- **WHEN** 开发或测试环境执行预置数据加载
- **THEN** 系统创建 A 班和 B 班，以及各自可登录的教师和学生账号

#### Scenario: 预置数据可重复加载
- **WHEN** 开发或测试环境多次执行预置数据加载
- **THEN** 系统不会创建重复账号或重复班级，并保持每个用户的密码字段为哈希值

#### Scenario: 生产环境不自动加载预置账号
- **WHEN** 应用以生产环境配置启动
- **THEN** 系统不自动创建预置账号、预置密码或测试材料

### Requirement: 受保护资源需要认证

系统 SHALL 要求访问受保护页面和受保护 API 的请求通过认证。未认证的浏览器请求访问受保护页面时 SHALL 被引导至登录页；未认证的 API 请求 SHALL 被拒绝，且不得暴露受保护数据。

#### Scenario: 未认证的浏览器访问被重定向
- **WHEN** 没有有效会话的用户请求受保护页面
- **THEN** 用户被引导至登录页，且不返回受保护页面内容

#### Scenario: 未认证的 API 访问被拒绝
- **WHEN** 没有有效会话或令牌的请求调用受保护 API
- **THEN** API 将该请求作为未认证请求拒绝，且不返回受保护资源数据

### Requirement: 角色权限在服务端强制执行

系统 SHALL 仅允许已认证教师上传教学材料。每个上传请求的授权检查 MUST 在服务端执行，且 MUST NOT 依赖客户端是否显示或隐藏上传控件。

#### Scenario: 教师上传材料
- **WHEN** 已认证教师为其所属班级上传有效教学材料
- **THEN** 服务端接受该上传进行处理，并将其关联到该班级的知识库

#### Scenario: 学生直接调用上传 API
- **WHEN** 已认证学生调用材料上传 API，包括绕过用户界面直接调用
- **THEN** 服务端以 HTTP 403 拒绝该请求，且不存储或索引该材料

### Requirement: 班级归属是服务端数据边界

系统 SHALL 将材料所有权、列表查询、读取和知识库操作限定在已认证用户所属班级内。服务端 MUST 从可信的已认证身份数据中推导班级范围，不能接受客户端提供的班级标识作为授权依据。

#### Scenario: 用户查询本班材料
- **WHEN** 已认证教师或学生请求材料列表
- **THEN** 服务端仅返回属于该用户所属班级的材料

#### Scenario: 用户尝试跨班级访问
- **WHEN** A 班用户请求、读取或修改属于 B 班的材料
- **THEN** 服务端拒绝该操作（至少对已认证但无权限的操作返回 HTTP 403），且不暴露 B 班材料的内容或元数据

#### Scenario: 客户端伪造其他班级标识
- **WHEN** 已认证用户在列表、上传或材料请求中提交其他班级的班级标识
- **THEN** 服务端忽略该不可信范围作为授权依据，并强制使用用户的实际班级归属

### Requirement: 上传材料成为可检索的知识库记录

教师上传成功后，系统 SHALL 持久化材料记录，并将上传材料写入该教师所属班级的知识库。写入完成后，班级材料列表 SHALL 展示新记录。

#### Scenario: 新上传的材料出现在班级列表中
- **WHEN** 教师上传成功完成
- **THEN** 同班成员随后请求材料列表时，列表返回该材料的记录，且跨班级用户无法在列表中看到该记录

#### Scenario: 上传失败不会创建可见记录
- **WHEN** 上传期间存储或知识库写入失败
- **THEN** 系统报告失败，且不会在班级列表中暴露成功材料记录

### Requirement: 密钥和服务健康状态受运维控制

系统 SHALL 从服务端环境变量或等价的密钥注入机制加载签名密钥、加密密钥和其他敏感服务配置。系统 SHALL 提供用于存活检查的 `GET /health`，并 SHALL 支持通过 Docker Compose 启动。

#### Scenario: 健康检查端点报告服务存活
- **WHEN** 正在运行的应用收到 `GET /health`
- **THEN** 应用返回成功的健康检查响应，且不要求用户认证

#### Scenario: 客户端不能提供密钥
- **WHEN** 客户端发起认证请求或受保护资源请求
- **THEN** 服务端使用已配置的服务端密钥，且不接受来自请求参数、表单数据或请求头的签名密钥或加密密钥

#### Scenario: Compose 可以启动应用和依赖服务
- **WHEN** 操作者使用配置好的环境变量执行 Docker Compose 启动
- **THEN** 应用及其持久化依赖成功启动，并可以通过 `GET /health` 返回成功响应
