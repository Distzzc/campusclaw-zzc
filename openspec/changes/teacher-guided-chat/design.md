## Context

见 `proposal.md` - Why。当前项目是 Flask + SQLite 单体应用，JWT Bearer 身份由数据库解析；`knowledge.web` 已提供教师/学生均可访问的本班检索、受保护原文与单轮 `/api/knowledge/ask`，后者在完成回答与引用核验后返回非流式 JSON。课堂前端通过 `static/js/app.js` 的带 Bearer `fetch` 调用 API。现有测试使用临时 SQLite、可替换知识/问答适配器和 Flask test client；目前没有持久化会话、教师提示词/技能配置或流式回答。

新功能在不改变单轮问答 API 的前提下复用以上检索和来源协议。规格详见 `specs/guided-learning-chat/spec.md`。用户已确认会话持久保存且仅学生本人可见，并选择先完成证据/引用核验再流式展示。

## Goals / Non-Goals

**Goals:**

- 让 SQLite 作为班级辅导配置、技能、会话及消息的持久化权威来源，严格校验教师角色、学生所有权和班级边界。
- 默认提供一项可编辑的启用中「解题引导」技能；配置变更原子化，任何成功状态都满足至少一项启用技能。
- 将教师配置作为受限的教学策略输入，不能覆盖服务端的证据、引用、身份和安全约束。
- 复用本班知识检索、来源生成和当前版本校验；在充分核验后才持久化完整回答并开始发送流事件。
- 复用当前 Bearer 前端请求和现有 UI 测试方式，无新增必需模型服务或在线依赖。

**Non-Goals:**

- 不允许教师查看学生私有会话，不提供跨学生共享、教师监控、跨班知识检索或课程级成绩分析。
- 不替换或破坏现有 `/api/knowledge/ask` 和材料检索接口，不引入会话以外的全局聊天记忆或联网工具调用。
- 不承诺模型可以在所有问题上完美判断何为“最终答案”；通过结构化引导输出、专门校验、失败关闭及真实模型验收降低风险。
- 不提供提示词市场、技能导入/导出或第三方技能执行环境。

## Decisions

### 使用关系数据库承载辅导配置与学生私有会话

- 增加 SQLite 表保存每班提示词配置、技能（class_id、名称、类型、内容、启用状态和更新时间）、会话（学生 ID、创建时班级、标题和时间）及消息（会话 ID、角色、正文、状态、引用 JSON 和时间）。通过外键/索引和服务端查询维持归属；引用保留 `chunk_id`、`content_version` 及展示所需出处字段，不把回答中的客户端来源作为事实。
- 数据库初始化时为已有班级幂等创建默认提示词配置和至少一项启用的内置「解题引导」技能；SQLite 迁移需兼容旧数据库并可重复执行。后续新增班级也必须获得有效默认技能。
- 技能写操作在 `BEGIN IMMEDIATE` 事务中检查教师班级和最终启用状态，拒绝删除/停用最后一项启用技能，避免并发教师操作破坏不变量。学生只读本人的会话；会话查询按 `session_id + student_id` 筛选，找不到或无权访问统一返回 404，避免探测存在性。教师配置查询按服务端 `class_id` 限定。
- 会话在创建时记录 `student_id` 与 `class_id`。每次继续会话仍同时校验当前认证学生 ID 和当前班级归属；学生转班后旧班会话不可跨班继续或读取。通过专门的本人删除操作清理私人会话及其消息；会话标题由学生填写或服务端生成，不依赖模型输出作为授权字段。

### 以结构化教学策略拼装提示，安全约束始终由服务端保留

- 将系统固定约束、服务端提供的当前班技能/教师附加提示、学生问题和证据分别作为独立结构化输入；教师文本不与系统级安全规则合并为可覆盖的 system 指令。教师提示词与技能正文采用明确字符上限（设计默认：提示词 4,000 字符，单项技能 2,000 字符），问题复用现有 2,000 字符上限。
- 生成目标为分步提示、澄清/反思问题和可选的下一步练习，不包含 `final_answer` 字段。对输出先做结构、引用原文子串、逐项证据支持校验，再由独立审核检查是否直接揭示题目最终结论；不通过时最多按配置重试一次，仍不通过则返回安全失败，不展示草稿。此审核遵循与现有证据审核相同的模型可靠性边界，不能当作形式化证明。
- 使用当前启用的「解题引导」技能和教师提示配置处理新问题；已存消息不会因为配置修改被重写。现有 `answer()` 为旧 API 保持原样，新增辅导生成入口复用知识检索结果和来源校验逻辑，避免把会话历史当作证据。若未来引入历史上下文，也必须与当前本班检索证据分开，并受 token 预算限制。

### 复用既有检索和来源协议，并在事务提交前重验权限与版本

- 新消息处理先按当前 JWT 用户及班级读取会话，然后调用现有知识服务的本班检索；不接收客户端 `class_id`、证据或引用。生成过程中使用的来源仅为本次检索结果。
- 接收问题时先持久化用户消息，状态为 `pending`。生成结束后逐项校验引用 ID、逐字引文、事实支持及引导式输出，并在持久化前再次检查 access token 未撤销/未过期、用户仍属原班、会话所有者有效，以及每条引用仍是材料当前可检索版本。成功时以同一数据库事务写入完整助手消息并将用户消息标记为 `completed`；失败时将用户消息标记为 `failed` 并保存安全的错误类别，不保存模型草稿或伪成功助手消息。失败问题可由学生在会话中重新提交，不覆盖此前消息。
- 将已核验的完整助手消息和引用写入 SQLite 后才建立流响应。这样模型失败或校验失败不会泄漏草稿；网络断开后数据库仍保存完整结果，客户端可重新读取会话恢复，而不会留下半条已完成消息。

### 通过 Bearer fetch 消费 SSE，但流式传输的是已核验结果

- 新增受保护的会话创建/列表/详情/删除接口，以及提交消息的流式接口。消息接口使用 `text/event-stream`（SSE）；浏览器继续用 `fetch` 附加 Bearer Token 并读取 `ReadableStream`，不用 `EventSource`（其不能按现有方式设置 Authorization 头）。
- 事件协议使用 `meta`（消息 ID/状态）、`delta`（已核验答案的连续文本片段）、`citations`（服务端构造的引用元数据）、`done`（持久化消息 ID及结束标记）和 `error`。正文按字符或小段拆分只用于逐步呈现，不声称模型 token 在核验前实时到达。依据不足在开始正文流前以明确状态结束；认证、生成、证据变化等可预见失败在提交响应头前返回正常 JSON 错误码，避免 HTTP 200 隐藏失败。
- 响应建立前完成全部生成、校验和消息持久化；SSE 期间不再执行模型或数据库写操作。前端遇到非 `done` 的断流时标记传输未完成，并通过重新读取会话恢复已持久化的完整回答；不把已读的局部 delta 当作完成答案。
- 控制问题长度、证据数量、生成预算、并发和总超时，沿用现有问答配置/错误语义。流请求必须由部署代理正确传输且关闭缓冲；上线前验证 Docker/Nginx 路径的首事件与逐步读取行为，并设置合理的代理超时。

### 渐进部署并保留旧问答路径

- 先部署幂等 SQLite 迁移与默认技能初始化，再启用教师配置和学生会话 API/UI。既有数据库中的材料、JWT、检索索引和 `/api/knowledge/ask` 不变。
- 可通过配置开关隐藏/禁用新辅导 UI 和 API 回退；回滚不删除会话表或学生数据。会话删除按明确 API 执行，不因部署回滚自动清除。
- 配置与会话仅存于应用 SQLite 持久卷；备份/恢复应包含这些新表。现有 `/app/data` Compose 卷可承载数据，不需要新基础设施。

## Risks / Trade-offs

- [Risk] 教师自定义文本可能包含提示注入或与安全目标冲突 → 将其作为受限的教学策略数据，服务端系统约束优先；提示、技能与材料分别隔离输入，并对引用和直接给出最终答案执行独立校验。
- [Risk] 语义审核无法完全证明回答没有泄露最终答案 → 采用无最终答案字段的结构化输出、拒绝/重试策略和边界样例验收；不合格时失败关闭，并在界面清楚说明重试。
- [Risk] 先核验后开始流意味着首次响应等待模型完成，流式仅改善完整答案的呈现体验而非模型首 token 延迟 → 将该取舍作为安全要求，呈现“正在检索/核验”状态，并对推理设置超时。
- [Risk] SSE 经反向代理缓冲，或客户端断线后误以为答案丢失 → 禁用该路由代理缓冲并集成验证；完整消息在流开始前已持久化，支持重载恢复。
- [Risk] 会话历史包含学生个人信息，数据库泄露或错误授权会扩大影响 → 最少保存必要内容、仅本人授权、错误时统一 404、提供删除能力；日志不得记录完整问题/回答/提示配置。
- [Risk] 多教师并发编辑技能可能移除最后一项有效技能 → 使用 SQLite 写事务串行检查并添加并发测试，初始化及迁移保持幂等。

## Migration Plan

1. 增加可重复执行的 SQLite schema 迁移；为现存班级创建默认提示词和内置解题引导技能，确认历史用户、材料及知识索引未被修改。
2. 实现教师配置 API 与不变量测试，再实现学生会话所有权、持久化及隔离测试；新增接口统一依赖当前 JWT 和服务端班级归属。
3. 实现辅导式生成及证据/引用/非最终答案审核，完成后再持久化并响应 SSE；使用确定性替身覆盖正常、拒答、核验失败、过期证据、超时和中断恢复。
4. 接入角色化界面，验证 Bearer 流读取、引用原文访问、移动布局、代理逐步传输及会话刷新恢复；执行现有单轮检索与问答回归测试。
5. 渐进启用辅导 UI/API。回滚时关闭新入口并保留数据库数据；如需撤回学生数据，由授权的数据删除流程显式处理。
