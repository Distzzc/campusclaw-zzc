## Why

现有课堂知识库支持单轮、非流式问答，但没有教师可控的教学引导方式，也不能让学生管理连续的学习会话。新增由教师维护的提示词与必备「解题引导」技能，并提供以本班知识库为依据、带出处且可持续查看的流式辅导会话，可让学习过程更有指导性，同时避免系统直接代替学生给出最终答案。

## What Changes

- 为教师提供提示词配置与技能维护能力，并保证每个班级始终至少启用一项「解题引导」技能；该技能须通过提问、提示和分步引导帮助学生推理，不直接给出最终答案。
- 为学生提供新建、查看和继续自己的持久化会话能力；会话及消息按学生本人隔离，其他学生和教师不能读取。
- 学生提问后，服务端先检索并核验当前班级知识库证据及引用，再把已校验的回答与引用以流式事件交付；证据不足时明确说明，不展示未经校验的生成草稿。
- 提供会话及问答 API 与课堂界面，覆盖加载、流式中断、无依据、服务错误和引用查看等状态。
- 保持现有 JWT 认证、角色授权、班级检索边界与材料来源校验；不改变既有单轮问答 API 契约。

## Capabilities

### New Capabilities
- `guided-learning-chat`: 教师提示词与解题引导技能管理，以及学生私有、持久化、基于本班知识库且先校验后流式输出的辅导会话。

### Modified Capabilities

无。仓库目前没有已发布的 `openspec/specs/` capability；既有检索、认证及前端行为分别保留在相关历史变更规格中。本变更通过新 capability 定义辅导会话行为，不改动现有 `/api/knowledge/ask` 单轮接口契约。

## Impact

- 预计扩展 `app.py` 的 SQLite 数据模型及迁移，为提示词/技能、学生会话和消息提供持久化，并实施教师与学生本人授权检查。
- 扩展 `knowledge/web.py` 与问答/知识服务，增加管理与会话 API；复用 `Knowledge.search`、来源版本校验及现有认证，不接受客户端提供的班级范围或证据。
- 扩展 `templates/dashboard.html`、`static/js/app.js` 和 `static/css/app.css`，增加角色化配置界面、学生会话列表和经过校验的流式交互。
- 扩展 Flask 与 UI 测试及文档；复用现有离线模型、适配器和测试替身，不要求引入新的模型依赖。具体流式传输协议与模型调用边界在设计工件中确定。
