## Why

当前系统可以上传并列出材料，但没有受保护的文件下载能力；用户只能看到材料元数据，且无法安全取得原始文件。课堂材料属于班级数据边界，下载必须在服务端重新校验登录身份和班级归属，防止不同班级之间发生文件泄露。

## What Changes

- 新增受保护的材料下载接口，例如 `GET /api/materials/<material_id>/download`。
- 教师和学生都可以下载自己所属班级中已成功入库的材料。
- 服务端从当前 session 获取用户 `class_id`，不信任客户端提交的 `class_id` 或 `storage_path`。
- A 班用户访问 B 班材料时返回 HTTP 403，不暴露文件内容、路径或资源元数据。
- 只允许下载 `index_status = 'indexed'` 且文件实际存在的材料。
- 使用安全的文件发送方式和受控存储根目录，防止路径穿越；下载文件名使用数据库中的原始文件名。
- 在现有材料列表中增加下载按钮，并复用现有认证会话和服务端权限逻辑。
- 增加登录、同班下载、跨班 403、未索引材料、文件缺失和路径穿越防护测试。

## Capabilities

### New Capabilities

- `secure-material-download`: 定义教师和学生下载本班已入库材料的接口、权限、错误和前端入口行为。

### Modified Capabilities

无。现有认证、角色授权、班级隔离和 Web 前端 capability 的既有要求保持不变，本变更增加下载这一受保护资源操作。

## Impact

- 修改 Flask 材料 API 和文件发送逻辑，新增下载路由及安全路径校验。
- 修改材料列表前端，增加下载操作和下载失败提示。
- 扩展 Flask/集成测试，覆盖认证、同班授权、跨班拒绝、状态过滤、文件不存在和路径穿越。
- 不改变 SQLite 材料表结构、上传流程、session 认证方式或 Docker Compose 部署方式。
